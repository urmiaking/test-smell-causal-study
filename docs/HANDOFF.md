# Team 7 — Developer handoff checklist

## Technical contract delivered
Key: (repository_id, snapshot_sha, test_file) represents a **single baseline test file**. Must match exactly across datasets. Commit refs are immutable. No test-method granularity is implied.

| Artifact | Producer | Consumer | Contract |
|---|---|---|---|
| tests.csv | Developer | Experimenter/Analyst | baseline test keys, production path candidate, framework heuristic, test metrics, detector_status |
| smells.csv | Developer | Analyst | long-form test+smell flags; measured true/false vs empty with not_applicable/invalid |
| outcomes.csv | Developer | Analyst | later file-change events using same baseline paths; followup_sha |
| commit_events.csv | Developer | Analyst | change proxies, not verified bugfix labels |
| raw/ and manifest.json | Developer | both | raw detector outputs, commit SHA and runtime provenance |
| PIT results CSV | Experimenter | Analyst | join on exact baseline file keys, explicit attribution method, score in [0,1] |

### PIT file schema

See contracts/pit-results.example.csv for the **header only**. There are no fabricated mutation scores in this repository.

Allowed measurement_status: measured, not_measured, failed, not_attributable.

For measured PIT rows, attribution_method must be exactly one of:
- isolated_test_file — mutations measured while isolating the test file; experimental procedure must be recorded
- verified_per_test_coverage — independently verified mutant-to-test attribution

Project-wide PIT score is NEVER a per-file outcome. For unmeasured rows, mutation_score must be empty. The Developer's validation checks only joins/ranges/declared attribution; the Experimenter and Analyst MUST verify methodology and logs.

### Commands for the other two team members

    python -m team7_pipeline validate --results results/RUN_ID
    python -m team7_pipeline validate --results results/RUN_ID --pit experiments/pit-results.csv --export results/RUN_ID/pit-joined.csv

For independent technical replication on another machine: install dependencies and exact approved JAR hash, clone/pin same source commits, create **new** run_id/output_dir, execute, and compare semantic CSVs with python -m team7_pipeline compare. Copying existing CSV files is not independent replication.

## Pending external signoffs (not generated by this software)

- [ ] Analyst: confirm DAG, confounders and causal estimand, outcome window and observation unit
- [ ] Team: approve representative GitHub inclusion/exclusion criteria, licensing and sampling bias
- [ ] Analyst: manually validate detector precision and inter-rater agreement

- [ ] Professor: go/no-go decision on pilot before large-scale causal analysis

## Limitations

Framework discovery is heuristic, JUnit 5 support of legacy tsDetect v2.2 is uncertain, file renames may be missed, and Regex bugfix commit messages are only noisy proxies. Raw files include personally-identifiable public Git authors and should be handled under project data policy.
